# Деплой статичного сайта на Cloudflare через GitHub

Деплой (публикация) это перенос сайта с компьютера туда, где его увидит весь интернет. GitHub здесь посредник: на нём лежит код, а Cloudflare сам забирает его оттуда. Один раз настроили связь, а дальше любое сохранение кода (`git push`) обновляет сайт само.

> Названия кнопок ниже проверены в панели Cloudflare в конце сентября 2026. Если у человека экраны выглядят иначе, опирайся на то, что он видит (см. правила в `SKILL.md`).

## Перед началом проверь

1. **Статичный ли сайт?** Посмотри в корень проекта. Если лежит `wrangler.jsonc` или `wrangler.toml`, это сайт с сервером, и шаги ниже подойдут частично. Скажи об этом человеку.
2. **Код уже на GitHub?** Если нет, помоги его туда отправить (промпт ниже).
3. **Есть аккаунты GitHub и Cloudflare?** Если нет, человек регистрируется сам:
   - GitHub: https://github.com/signup
   - Cloudflare: https://dash.cloudflare.com/sign-up
   Регистрация на обоих бесплатна, банковская карта для неё не нужна.

### Подготовить код к отправке на GitHub

Если у человека есть Claude Code с доступом к папке проекта, сделай это сам, показывая вывод команд:

1. Проверь `git status`. Если папка ещё не репозиторий, выполни `git init`.
2. Если нет `.gitignore`, добавь (исключи `node_modules`, `.env`, `.DS_Store`).
3. Проверь, что в коде нет ключей и паролей. Если есть, остановись и скажи об этом.
4. Закоммить изменения. Если git пишет, что не знает, кто автор (ошибка про `user.name` / `user.email`), спроси у человека имя и почту и задай их только для этого проекта (`git config user.name ...` без `--global`).
5. **Репозиторий на GitHub человек создаёт сам.** Скажи ему: на github.com кнопка **New** → придумать название → выбрать Public (виден всем) или Private (виден только вам) → **Create repository**. Важно **не ставить галочки** «Add a README», «.gitignore», «license»: репозиторий должен быть пустым, иначе первая отправка упрётся в конфликт. После создания человек присылает ссылку вида `https://github.com/ник/название.git`.
6. Подключи репозиторий и назови ветку `main`:
   ```bash
   git remote add origin https://github.com/ник/название.git
   git branch -M main
   ```
7. **Перед `git push -u origin main` спроси согласие.**

Если при отправке появляется «Authentication failed» или просьба ввести пароль: GitHub не принимает обычный пароль для git. Предложи войти через GitHub CLI (`gh auth login`) или через приложение GitHub Desktop. **Не проси человека присылать тебе токен или пароль** в чат.

## Шаги в Cloudflare

Каждый шаг выполняет человек. Ты объясняешь и сверяешься с тем, что он видит.

1. **Открыть раздел Workers & Pages.** Панель https://dash.cloudflare.com/ → боковое меню → Workers & Pages. Там кнопка **Create application**.
2. **Create application → «Make something new».** На экране варианты: Continue with GitHub, Connect with GitLab, Start with Hello World!, Select a template, Upload your static files.
3. **Continue with GitHub.**
   - Если GitHub ещё не подключён к Cloudflare, откроется запрос на доступ. Человек решает сам: объясни, что Cloudflare получает доступ к выбранным репозиториям. Лучше дать доступ только к нужному репозиторию.
   - Если уже подключён, сразу откроется экран **«Select a repository»**.
4. **Select a repository.** Выбрать репозиторий из списка (есть поиск) → **Next**. Если репозитория нет в списке, значит, Cloudflare не получил к нему доступ. Вернуться к подключению GitHub и выдать доступ к этому репозиторию.
5. **«Set up your application».** Поля:
   - **Project name**: от него зависит адрес `название.pages.dev`. Подставляется имя репозитория. Проверь, что оно не совпадает с другим проектом человека, и при желании поменяй.
   - **Build command**: можно оставить пустым (подпись Optional), если у сайта нет сборки.
   - Для чистой статики ожидай поля вроде framework preset и build output directory. Output directory это папка, где лежит `index.html`; если он в корне, ориентируйся на подсказки на экране. Эту часть экрана в нашей проверке на «чистой» статике не видели: сверяйся с тем, что показывает панель.
6. **Deploy.** Кнопка внизу экрана. Cloudflare сам скачает код и опубликует сайт, обычно это занимает минуту-две. Появится технический адрес `*.pages.dev`: откройте его и проверьте сайт.

### Про ветку

Явного выбора production branch на экране настройки мы не увидели: похоже, берётся ветка по умолчанию на GitHub (обычно `main`). Поэтому заранее проверь, что в репозитории ветка по умолчанию та, которую человек считает основной. Если на экране есть отдельное поле выбора ветки, выбирай `main` (или нужную).

## Как работает обновление

- `git push` в основную ветку: Cloudflare собирает новую версию и обновляет сайт.
- `git push` в любую другую ветку или пул-реквест: отдельный адрес для проверки (preview), основной сайт не меняется.

Для одного человека этого достаточно: правишь код, коммитишь, пушишь (с согласия), через минуту-две сайт обновился.

## Лимиты (на конец сентября 2026)

- Раздача сайта посетителям бесплатна, лимита по трафику на статику нет.
- Лимит на сами деплои: на бесплатном тарифе 500 сборок в месяц (примерно 16 в день), одна сборка одновременно. Каждый `git push` в подключённую ветку считается сборкой.
- Сборка, идущая дольше 20 минут, обрывается.

Цифры могли измениться: сверить можно в документации Cloudflare Pages (раздел Limits).

## Если что-то пошло не так

- **Деплой упал.** В проекте Deployments → View build history → нужный деплой → Logs. Там написано, на каком шаге и почему. Частые причины: опечатка в пути к файлу или неверная папка с `index.html`. Попроси человека прислать текст ошибки и разбери его.
- **Сайт не обновился.** Проверь по порядку: сделан ли `git push` и дошёл ли коммит до GitHub; прошла ли сборка успешно; не закэширована ли страница в браузере (обновить принудительно: Cmd+Shift+R или Ctrl+F5).
- **Новая версия сломала сайт.** В истории деплоев можно выбрать предыдущий успешный деплой и сделать его активным (откат), не удаляя коммиты.
- **Прямая загрузка без GitHub.** В «Make something new» есть вариант **Upload your static files**. Подходит для разовой выкладки, но каждое обновление придётся загружать вручную.

## Привязать домен

Если домен куплен в этом же аккаунте Cloudflare: в проекте раздел Custom Domains → добавить домен, DNS настроится сам. Если домен куплен в другом месте (например, на Reg.ru), нужно переключить nameservers на Cloudflare. Подробно: `references/buy-domain.md`.
