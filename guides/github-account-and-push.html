GitHub: аккаунт и заливка проекта

Анастасия Малютина · MONOLITH · ~10 мин чтения

Как завести аккаунт на GitHub, создать репозиторий и отправить туда папку с проектом: через нейронку, через программу с кнопками или командами. После этого код лежит в облаке и готов к публикации сайта.

01 Что такое GitHub и как выбрать путь

GitHub — сайт, где хранятся проекты с полной историей изменений. Это облачная копия вашей папки: сломался компьютер, а проект жив. Кроме того, отсюда сервисы публикации сайтов (например, Cloudflare) забирают код и выкладывают сайт сами при каждом обновлении.

Git и GitHub — не одно и то же. Git — программа на вашем компьютере, она запоминает версии файлов. GitHub — сайт, куда эти версии отправляют. Подробнее в гайде про Git.

«Залить проект» значит отправить папку с проектом в репозиторий (хранилище проекта) на GitHub. Команда для этого называется git push, по-русски «запушить».

Выберите свой путь

Как вы работаетеЧто читать

Что понадобится: компьютер, папка с проектом, почта, на которую можно принять письмо.

02 Шаг 1. Аккаунт на GitHub

Это делается руками: вы вводите свою почту и пароль, нейронка этого за вас не сделает.

  1. Откройте github.com/signup.
  2. Введите почту, придумайте пароль и username. Username станет частью адреса всех ваших проектов (github.com/ваш-username/проект), его видят все. Выберите то, что не стыдно показать: имя, ник, название студии. Позже его можно сменить, но ссылки на старый адрес перестанут работать.
  3. Пройдите проверку «не робот» и подтвердите почту кодом из письма. Порядок экранов может отличаться.
  4. Включите двухфакторную защиту (Settings → Password and authentication → Two-factor authentication). В аккаунте будет лежать код ваших проектов, лучше защитить его вторым шагом входа.
Почта для коммитов

Каждое сохранение в Git подписывается вашей почтой, а в публичном репозитории подпись видна всем. Если не хотите светить настоящую, в настройках GitHub (Settings → Emails) есть пункт «Keep my email addresses private» и специальный адрес вида …@users.noreply.github.com. Его можно указать вместо настоящей почты, когда будете настраивать Git (см. «Руками в терминале»).

03 Шаг 2. Пустой репозиторий

Репозиторий (коротко «репо») — папка проекта на GitHub.

  1. Нажмите «+» в правом верхнем углу → New repository (или кнопку New на главной).
  2. Repository name — название проекта латиницей, без пробелов: my-site.
  3. Public или Private:
    • Public — код видят все, кто знает ссылку. Подходит для сайта-портфолио.
    • Private — виден только вам и тем, кого добавите. Выбирайте, если в проекте есть что-то личное.
  4. Ничего больше не отмечайте. Галочки «Add a README file», «Add .gitignore», «Add a license» оставьте выключенными. Если репозиторий создан с файлами, а на компьютере тоже есть свои, при первой отправке Git откажет (ошибка rejected, см. ниже), потому что у них разные истории.
  5. Нажмите Create repository.

Откроется страница с подсказкой «Quick setup». На ней нужна ссылка вида https://github.com/ваш-username/my-site.git. Скопируйте её.

Public и секреты

В публичный репозиторий не должны попасть пароли и ключи (файл .env). Если ключ однажды попал на GitHub, считайте его украденным и замените. Подробнее: раздел про безопасность в гайде про Git.

04 Через нейронку (самый короткий путь)

Подходит, если у вас Claude Code, Codex, Cursor или другой клиент, который работает в папке проекта и запускает команды. Шаги 1 и 2 (аккаунт и пустой репозиторий) всё равно делаются руками. Установку Git и вход в GitHub тоже лучше сделать заранее: нейронка может предложить установить gh, но пароль от аккаунта вводите только вы, в браузере.

Откройте нейронку в папке проекта и отправьте:

Промпт для нейронки — залить проект на GitHub 
Я хочу залить этот проект в новый пустой репозиторий на GitHub:
[вставьте ссылку вида https://github.com/ваш-username/my-site.git]

Сделай по порядку и показывай результат каждой команды:
1. Проверь, установлен ли git и настроены ли user.name и user.email. Если нет, спроси у меня имя и почту и настрой.
2. Если в проекте нет git, выполни git init -b main.
3. Если нет .gitignore, создай подходящий под тип проекта и обязательно добавь туда .env, node_modules и .DS_Store.
4. До первого коммита покажи список файлов, которые собираешься сохранить, и остановись, если среди них есть пароли, ключи, файлы .env или огромные файлы.
5. Сделай первый коммит с подписью «Первый коммит».
6. Привяжи репозиторий по ссылке как origin и отправь ветку main.
7. Если GitHub попросит войти, не придумывай обходных путей и не проси у меня пароль в чате: подскажи войти через gh auth login или GitHub Desktop.
В конце покажи ссылку на репозиторий и git log --oneline.

Что происходит под капотом, смотрите в разделе «Руками в терминале». Это те же команды.

05 Через программу с кнопками

Клиент делает то же, что команды, но кнопками, и сам разбирается со входом в GitHub. Для новичка это самый спокойный путь.

GitHub Desktop (desktop.github.com, бесплатно, Mac и Windows):

  1. Скачайте, установите и войдите в аккаунт GitHub (откроется браузер).
  2. File → Add Local Repository → выберите папку проекта. Если папка ещё не под Git, программа предложит создать репозиторий (create a repository).
  3. Слева появится список изменённых файлов. Внизу напишите подпись («Первый коммит») и нажмите Commit to main.
  4. Нажмите Publish repository, выберите Public или Private. Программа сама создаст репозиторий на GitHub и отправит проект.

Если пользуетесь этим способом, шаг 2 (пустой репозиторий на сайте) можно пропустить: «Publish repository» создаёт его сам. Fork и другие клиенты работают по тому же принципу, их выбор разобран в гайде про Git. В Fork репозиторий на GitHub создаётся на сайте (шаг 2), а потом в программе добавляется ссылка на него и нажимается Push.

06 Руками в терминале

Нужно, только если нет ни нейронки с доступом к папке, ни клиента. Выполняйте в папке проекта. Как открыть терминал, объяснено в гайде про Git.

git config --global user.name "Ваше Имя"
git config --global user.email "you@example.com"
git init -b main
git add .
git status
git commit -m "Первый коммит"
git remote add origin https://github.com/ваш-username/my-site.git
git push -u origin main

Что здесь важно знать:

  • Имя и почта (первые две строки) нужны один раз на компьютере. Без них коммит не получится (Author identity unknown). Почту можно взять из аккаунта GitHub или специальную noreply (см. шаг 1).
  • .gitignore создайте до git add .: файл со списком того, что нельзя сохранять. Впишите туда .env, node_modules/, .DS_Store. Нейронка подготовит список под ваш проект.
  • git status перед коммитом показывает, что попадёт в сохранение. Если видите .env или ключи, остановитесь и поправьте .gitignore.
  • Ссылку для remote add берёте со страницы пустого репозитория (шаг 2).
  • Вход в GitHub. Пароль от аккаунта Git не принимает (Authentication failed, это нормально). Самый простой вход: установите GitHub CLI (cli.github.com) и один раз выполните gh auth login, выбрав вход через браузер. Подробнее про gh в гайде про Git. Вход можно сделать и в GitHub Desktop. Длинные ключи-токены новичку не нужны.

Проверьте результат: откройте страницу репозитория и обновите её. Должны появиться файлы, подпись «Первый коммит» и счётчик коммитов. Дальше обновления отправляются тремя командами: git add ., git commit -m "...", git push, или просто фразой «закоммить и запушь» нейронке.

07 Через браузер (если файлов совсем немного)

На странице пустого репозитория есть ссылка uploading an existing file, а в любом репозитории кнопка Add file → Upload files: файлы перетаскиваются в окно браузера, внизу нажимается Commit changes. Работает без Git и терминала.

Минусы:

  • у такой загрузки есть лимиты на число и размер файлов (порядка сотни файлов за раз и десятков мегабайт на файл), точные цифры смотрите в документации GitHub;
  • каждое обновление придётся заливать так же вручную;
  • нет привычной истории с подписями;
  • сервисы автодеплоя работают с любым репозиторием, но удобнее всего, когда обновления приходят через git push.

Для одноразовой странички подойдёт, для живого проекта лучше один из способов выше.

09 Public или Private: что выбрать

  • Private — по умолчанию безопаснее: код видите только вы. Приватные репозитории на личном аккаунте GitHub бесплатны.
  • Public — разумный выбор для сайта-портфолио, который и так открыт всем. Главное: в публичном репозитории не должно быть ничего личного.
  • Публиковать сайт можно из репозитория любого типа: документация Cloudflare Pages прямо пишет, что поддерживаются и публичные, и приватные репозитории. Так что делать репозиторий публичным ради деплоя не нужно.
  • Видимость можно сменить в любой момент: в Settings репозитория.

10 Чек-лист

  1. Аккаунт создан, почта подтверждена, включена двухфакторная защита.
  2. Username такой, который не стыдно показать.
  3. Создан пустой репозиторий (без README и лицензии), выбран Public или Private.
  4. Git установлен, имя и почта настроены.
  5. .gitignore создан ДО первого git add, в нём .env.
  6. Перед коммитом посмотрела git status: в списке нет паролей и ключей.
  7. Вошла в GitHub через gh auth login или GitHub Desktop.
  8. git push прошёл, файлы видны на странице репозитория.

11 Частые вопросы

Это бесплатно?
Аккаунт и хранение личных проектов, в том числе приватных, бесплатны.
Нужно ли уметь программировать?
Нет. Команды одинаковые для любого проекта, их достаточно запомнить как порядок: добавить, сохранить, отправить.
Нужен ли терминал?
Нет, если использовать GitHub Desktop или нейронку, которая запускает команды сама.
Можно ли сменить название репозитория или username потом?
Можно, но старые ссылки перестанут работать, а локальную привязку придётся обновить командой git remote set-url origin <новая ссылка>.
Что значит main?
Название основной ветки проекта. Старые проекты называют её master, смысл тот же.
Что делать дальше?
Подключить репозиторий к Cloudflare (гайд про деплой) и привыкнуть сохранять работу коммитами (гайд про Git).
