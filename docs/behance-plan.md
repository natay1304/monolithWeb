# Behance — контент под кейсы

Профиль Behance уже существует, здесь — что грузить в проекты и что снимать дальше.
Источник кейсов: `content.js`, `ARCHIVE_ITEMS`, `kind: 'case'`. Правила съёмки —
[cases-shotlist.md](cases-shotlist.md). Правило чести — из [offer-part-8.md](offer-part-8.md) п.6:
демо-кейсы на открытых/собственных моделях подписываются честно, выдуманных клиентов не бывает.

## Общие правила оформления проекта на Behance

**Порядок модулей** (Behance даёт ленту сверху вниз, первый экран решает, долистают или нет):

1. Обложка проекта (Project cover) — тот же hero-кадр, что и `media` на сайте, 1400×1050 или 808×632, не растягивать
2. Герой-кадр на белом крупно, без текста на самой картинке
3. Контекстные/дополнительные ракурсы
4. «Как сделано» — разрез / взрыв-схема / wireframe. Это блок, который на Behance держит дольше всего:
   аудитория площадки — такие же исполнители, их держит процесс, а не только результат
5. Контактный лист / доказательство консистентности серии — если кейс про серию (racking)
6. 360° / видео, если есть (превью-кадр + ссылка или встроенный mp4)
7. Последний блок — credits: пайплайн, инструменты, честная подпись источника модели, ссылка на сайт

**Теги** — до 10, без `#`, 1–3 слова каждый. Смешивать широкие и нишевые:
`3D Visualization`, `CGI`, `Product Rendering`, `Industrial Design`, `Blender`, `Cycles Render`,
плюс нишевые под конкретный кейс (`Warehouse Racking`, `Power Tool`, `Hydraulic Cylinder`).

**Tools used** (поле Behance) — по факту пайплайна: `Blender`, `Cycles`, `Python` (генератор/батч),
при необходимости добавить используемый AI-инструмент для среды/финиша, когда он реально применялся.

**Текст описания** — по формуле «инженер для инженера» (оффер, п.7): без превосходных степеней и эмодзи.

```
[Задача в одном предложении]

Deliverable: [список: ракурсы / разрез / взрыв-схема / 360° / серия SKU]
Формат исходника: [STEP / IGES / STL / OBJ / FBX / DXF — что применимо]

⚠️ Демонстрационный проект на [открытой / собственной параметрической] модели.
[источник, если открытая: автор/платформа]. Не связан с реальным клиентом.
```

Не кросс-линковать на второй бренд/сайт (правило «два бренда без перекрёстных ссылок» — оно про
второй сайт, не про сам Behance→monolith.studio, ссылку на сайт-портфолио в credits оставлять можно).

## Готов к публикации — CASE_03, складские стеллажи

Изображения уже лежат в `assets/cases/case-racking-01..05.jpg`, порядок в `content.js`
(`gallery`): 01 (сводный ряд) → 02 → 04 → 05 → 03.

**Title:** `WAREHOUSE RACKING — SKU SERIES` / RU: `Складские стеллажи — серия SKU`

**Порядок модулей в проекте:**
1. `case-racking-01.jpg` — сводный кадр всего ряда (обложка + первый экран)
2. `case-racking-02.jpg`, `04.jpg`, `05.jpg` — отдельные типоразмеры
3. `case-racking-03.jpg` — контекстная сцена
4. Контактный лист 20 миниатюр (сгенерировать: `node tools/contact-sheet.js assets/cases`) —
   это и есть блок «как сделано»/доказательство консистентности для серии

**Описание:**
```
Один параметрический стеллаж → 20 SKU в едином стиле без пересъёмки на позицию.

Deliverable: 20 позиций серии (высота рамы × длина балки), 3 контекстные сцены,
1 сводный кадр серии.
Формат исходника: параметрическая модель, генератор на Python + Blender/Cycles.

⚠️ Демонстрационный проект на собственной параметрической модели, без привязки
к реальному клиенту или производителю.
```

**Теги:** `3D Visualization`, `CGI`, `Product Rendering`, `Industrial Design`, `Warehouse`,
`Racking System`, `Blender`, `Cycles Render`, `Parametric Design`, `Catalog`

## Новые кейсы — предложения на съёмку

Ниже — какие кейсы имеет смысл сделать следующими. Логика подбора: закрыть те deliverable
из прайса (оффер, п.9), которых пока нет ни в одном кейсе, и разнести ниши, чтобы Behance-тегами
и обложками цепляло разные отрасли, а не три раза «промышленная деталь на белом».

Уже закрыто: каталожный пакет + взрыв-схема (CASE_01), разрезы + 360° (CASE_02),
серия SKU + консистентность (CASE_03). Не закрыто: **контекстная сцена**, **интерактив/AR**,
**видео о продукте**, **конфигуратор**, **дилерский пакет по спецификации**.

| # | Кейс | Ниша | Deliverable, которого не хватает | Источник модели |
|---|---|---|---|---|
| 1 | Строительный генератор / компрессор в цеху | Строительное оборудование | **Контекстная сцена**: тот же объект на площадке при дневном свете и в цеху при рабочем свете, с человеком для масштаба | GrabCAD, поиск «diesel generator», «air compressor» |
| 2 | Ручной электроинструмент — короткое видео принципа работы | Инструмент (продолжение CASE_01, но видео) | **Видео о продукте** 30–60 сек: как срабатывает механизм/патрон, без звука или с минимальным | Sketchfab / Thangs, «drill», «impact driver» |
| 3 | Модульный конвейер или роликовый стол | Логистика/производство | **Конфигуратор**-логика: 3–4 комплектации длины/ширины показать как набор, не как серию (отличие от racking — здесь варианты собираются из модулей, а не масштабируются) | GrabCAD, «roller conveyor module» |
| 4 | Насос или клапан с интерактивным просмотром | Промышленная арматура | **Интерактивный 3D**: `<model-viewer>` embed прямо в описании проекта Behance (Behance поддерживает встройку через ссылку/embed) — единственный кейс, где смотрящий сам вращает модель | Thangs, «industrial valve», «centrifugal pump» |
| 5 | Мебельный модуль (продолжение Sofa) | Мебель / HoReCa (расширение из п.8.10 оффера) | **Дилерский пакет по артикулу**: один диван в 4 обивках/цветах, карточка на каждый SKU + сводная сетка | Собственная модель Sofa, если разрешение на публикацию уже получено — иначе отдельная открытая модель |
| 6 | Лабораторный штатив / медтех-корпус | Медтехника/лаборатории (п.8.10) | **AR-сцена**: скриншот/запись объекта в реальном масштабе через телефон (даже без полноценного AR-приложения — можно `<model-viewer ar>`) | Sketchfab, «lab equipment», «medical device housing» |

**Приоритет:** 1 и 2 — минимальные по трудозатратам и закрывают самые частые запросы клиентов
(контекст и видео, п.8.3 оффера). 4 и 6 продают саму способность делать интерактив/AR, которой
пока нет ни в одном кейсе на сайте. 3 и 5 — когда будет время на связку из нескольких кейсов
в одной нише (логистика уже представлена racking, мебель — уже есть Sofa).

Для каждого — обязательна честная подпись источника (открытая модель) или пометка «собственная
параметрическая модель», как в CASE_03. Выдуманных клиентов и логотипов не создавать (оффер, п.8).
